## Implementation

- Public React UI and its deterministic browser Worker remain intact. The separate AI panel accepts a private access code, starts a fresh backend review, displays provenance, exact source links, coverage/refusals, cancellation, selected findings and human-approved Markdown.
- `api/[...path].ts` reuses the binary-streaming Node adapter and lightweight ingestion. `api/agent.ts` is a **separate** Node 24 Function; only that bundle contains Babel and backend evidence validation. Both use raw bodies, a 30-second application deadline and a 40-second platform duration. The 12-request/six-source/128-KiB/100-file limits are unchanged.
- `WorkersAiAdapter` transports the existing M5 model protocol to one private native-binding service. Gemma selects tools and proposes existing canonical fact cards. Both the relay and engine enforce strict JSON decision schemas. No SDK, framework, new risk family, automatic retry or fallback is added. Malformed/truncated output fails closed.
- Native calls use `@cf/google/gemma-4-26b-a4b-it`, `max_completion_tokens: 2048`, `chat_template_kwargs.enable_thinking: false`, `stream: false`, `n: 1`, `temperature: 0`. No function execution, tool provider, JSON Schema request, or external investigation is delegated to Cloudflare. Calls are limited to 48 KiB of model-request JSON, 32 KiB of decision output, 18 seconds at the binding boundary and 20 seconds on Node. The original agent has at most 16 model decisions/steps and 12 read-only tool calls, including its independent final verification within 30 seconds.
- A successful binding response must have exactly one `chat.completion` assistant message, `finish_reason: stop`, usage within bounds and a valid decision. Reported nonzero reasoning tokens are rejected. The completion bound includes generated reasoning where the provider counts it; disabling thinking is requested and the live contract must be checked again before release. No adapter label or mock test proves that inference occurred in production.
- Node independently reacquires public pinned GitHub evidence. Browser findings are never accepted. Only the existing NaN, recognized HTTPS Agent TLS opt-out and recognized JWT expiration opt-out predicates can be certified. Comments, strings, unsupported narratives, weak matches and changed source coordinates remain refused.

## Access, abuse and resource controls

Live endpoints require a private random access code. Authentication sets a signed 30-minute `HttpOnly; Secure; SameSite=Strict; Path=/api` cookie. This is an access gate, not an account system. Codes are cleared from React after login and are never put in frontend configuration or browser storage. Server secrets stay in Vercel/Cloudflare secret configuration. No permissive CORS, arbitrary proxy, GitHub credential or write operation exists.

Process memory cannot coordinate Vercel instances. One Cloudflare **SQLite-backed Durable Object** is proposed specifically for atomic admission, replay prevention and shared quota reservations. This is the demonstrated requirement for this one small resource; it is not a PR database or distributed analysis system. Durable state contains **only counters, grant IDs and timestamps**, never source, prompts, findings, credentials or request logs.

| Shared project control               | Limit                                                    |
| ------------------------------------ | -------------------------------------------------------- |
| Login attempts                       | 6/minute, 30/rolling hour, including wrong codes         |
| Reviews                              | 4/rolling hour, deterministic and AI combined            |
| Active capture/agent                 | 1 global, expiring at 30 seconds                         |
| Model decisions                      | 16/review, 64/UTC day                                    |
| Estimated Neuron reservation ceiling | 2,000/UTC day                                            |
| Agent draft retention                | RAM only, 4 drafts, 5 minutes, 512-KiB engine result cap |

Four review admissions reserve a worst-case 48 GitHub requests/hour for this application. This **does not reserve** GitHub's shared 60/hour originating-IP quota: other Vercel users and applications may exhaust it. Existing upstream headers, final-verification reservation, cooldowns and no-retry behavior still apply. Authenticated callers can consume the small shared allowance, causing deliberate denial of additional reviews; the service fails closed rather than spending or bypassing limits. Provider authentication is backend-only. Vercel's included platform protections remain necessary for HTTP-level denial-of-service; these app counters cannot bound unsolicited platform invocations.

Unknown provider outcomes also hold the active review lease until its original expiry. AI grants expire after 30 seconds and each turn is reserved durably before dispatch; duplicate/replayed turns fail. Estimated cost uses actual message UTF-8 bytes plus 1,024 template tokens as an input-token allowance and 2,048 completion tokens. Published pricing checked November 13, 2026 is 9,091 input / 27,273 output Neurons per million tokens. Valid usage settles the reservation; errors, malformed responses, cancellation and unknown outcomes retain it. This is a conservative **estimate**, not an enforceable provider per-call Neuron quota. A provider that continues after client abort may consume quota; no retry is issued. The account-level 10,000-Neuron daily Free allocation is shared with Projects 1 and 2, and their usage may change concurrently. No zero-impact claim is made. [Current pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [model contract](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/).

Canonical drafts stay only in coordinator **RAM** so approval works across Node instances without persisting PR content. Eviction/restart loses them and returns `DRAFT_EXPIRED`; approval is never reconstructed from browser findings. Human approval binds session principal, run ID, digest and selected indexes to that canonical draft, consumes it once, then reuses the existing gate. It permits **manual copy only**. There is no publication API. A new review would require a deliberate user action and another admission.

Deployed acceptance verified the smaller fixture/incremental streaming, then the final run verified the maximum transfer and error/cancellation behavior on the tested path. A production app review remains unverified because agent acceptance failed.

Required server environment is in `.env.example`. Before any deployment, set every required variable in **both Preview and Production**, inspect metadata with `verifyReleaseEnvironment`, and deploy explicitly to **Production**. Verify actual deployment identity/target/READY with `verifyReleaseDeployment`; do not infer it from a CLI flag. This corrects the first-deployment environment mismatch observed in M4.5. Operator acceptance secrets must also exist in both scopes for the acceptance artifact only. Configured `PRISM_PUBLIC_ORIGIN` plus Vercel's trusted system `VERCEL_URL` form a finite Host allowlist; forwarded host/protocol never configure it. App requests remain same-origin. Default secrets missing, malformed origins and unknown hosts fail closed.

Normal `.vercel/output` contains no operator routes or fixture assets. After `npm run build`, `npm run prepare:transport-probe` and `npm run prepare:release-acceptance` generate a **separate ignored local acceptance artifact** reusing the existing streaming harness and fixed synthetic GitHub fixtures. They create no cloud resources. The fixture route requires both a signed user session and a backend-only random operator secret, no caller prompts, no request body, a maximum one-hour window and native-binding calls only when authorized. Never deploy the old M4.5 runner: it has its own obsolete experiment identity/cleanup flow.
