**Protocol-2 implementation history.** The authorized run on this protocol produced 13 valid native decisions, then failed on an inventory loop. Current model protocol 3 adds backend-owned progress capabilities. See [actual result and focused correction](AI-TOOL-PROGRESS.md).

## Implemented correction

Transport acceptance remains passed. The previous synthetic run accepted one `getPullRequest` decision, then refused decision 2 as `INVALID_MODEL_RESPONSE`. Its raw output was intentionally not retained, so the evidence cannot distinguish malformed JSON from a schema mismatch. No provider outage or particular malformed payload is established.

Model protocol **2** removes canonical finding objects from decisions. The five existing backend interfaces and state machine remain. The model can:

- Investigate with `getPullRequest({})`, `listChangedFiles({offset,count})` or `readFileContext({path,startLine,endLine})`.
- Propose `createReviewFinding({kind,path,line})`. The backend retrieves the observed line from its private pinned capture, checks the actual added diff coordinate and existing AST predicate, and constructs severity, explanation, evidence, recommendation and source URL itself.
- Recheck an issued `validateReviewFinding({evidenceId})`, then `finish_review({findingIds:[ids]})`, including an empty selection, or `refuse_review({reason})`.

The model sees compact fact-card references: `evidenceId`, kind, path and line. It cannot supply final narrative, severity, URLs or evidence text. Unknown/cross-run IDs are rejected. Every selected ID is independently resolved and revalidated at finalization; a prior tool verdict never bypasses that check. Duplicate IDs are refused. No deterministic matches become AI proposals without model investigation, hypothesis and selection. Three supported risk categories, budgets, pinned-SHA capture, prompt-injection boundaries, coverage, cancellation and human approval are unchanged. Browser-computed findings remain untrusted outside the local UI.
